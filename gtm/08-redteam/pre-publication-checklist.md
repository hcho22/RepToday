## Measurement (from the fixed kill criteria)

- [ ] Instrument the funnel before TestFlight: onboarding -> first session, D7/D30 cohorts, weekly active exercisers, trial starts, paid conversions.
- [ ] **Read K5's install count off App Store Connect units, not off the telemetry `app_install` count.** US-T06 made collection opt-out, so an opted-out install is absent from the telemetry plane entirely; K5 is the one criterion judged against an **absolute** floor (~90/week), so every opt-out deflates it one-for-one instead of cancelling out of a ratio, and K5 could fire with nothing wrong (`07-thesis/investment-thesis.md`, third instrument rule; `06-channels/event-metric-schema.md` honest constraints). App Store Connect is an instrument the thesis already relies on for K9, not a new dependency. Wire the K5 read to it when the measurement is set up, before the week-8 review.
- [ ] **Check the pre-registered opt-out revisit trigger at each review.** The thesis deliberately moved no band, threshold, or floor for the opt-out, because the opt-out rate is unobservable until something ships. Its stated condition: the revisit becomes due the first time App Store Connect units and the telemetry install count both exist for the same period, since the gap between them *is* the opt-out rate. Nothing else in the package will prompt anyone to check this, which is why it is an item here rather than only a sentence there. Note that the 200-user minimum-cohort floor now means 200 *consenting* users, so it takes more than 200 real installs to reach.
- [ ] Pre-register the K8 wedge-comprehension rubric (written coding criteria, 25+ observed first runs, non-founder coding) before the first cohort, per the skeptic's fix.
